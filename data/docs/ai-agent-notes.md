# AI Agent 技术笔记

## 什么是 AI Agent

AI Agent（智能体）是让大语言模型从「一问一答」走向「自主完成任务」的系统。一个典型的 Agent 具备三个关键能力：自主决策（决定下一步做什么）、工具使用（调用外部能力）和记忆（跨步骤保持信息）。

与传统程序不同，Agent 的行为不是由固定流程写死的，而是由模型根据当前状态动态决定的。这带来了灵活性，也带来了不确定性，因此工程上需要用约束、回退和评测来控制它。

## 核心组件

一个完整的 Agent 系统通常包含四个部分：

**规划（Planning）**：把复杂目标拆解成可以执行的步骤。常见模式有任务分解、反思与修正、以及先规划后执行。

**记忆（Memory）**：短期记忆指当前上下文窗口内的对话和中间结果；长期记忆一般采用外部存储方案，最常见的是向量数据库——把历史信息向量化后存入，需要时通过语义检索召回相关内容。

**工具（Tools）**：Agent 通过调用工具与外部世界交互，例如搜索、计算、读写文件、调用 API。工具调用让模型突破「只会生成文本」的限制。

**执行循环（Execution Loop）**：Agent 反复执行「思考 → 行动 → 观察」的过程，直到任务完成或达到终止条件。

## 经典范式

### ReAct

ReAct（Reasoning + Acting）是最有影响力的 Agent 范式之一。它的核心思想是让推理（Reasoning）与行动（Acting）交替进行：模型先输出一段思考，再决定调用哪个工具，拿到工具结果（观察）后继续思考，如此循环。

这种交替结构的好处是可解释性——每一步的思考过程都显式输出，出错时容易定位是哪一步的推理或工具调用出了问题。

### Plan-and-Execute

Plan-and-Execute 模式先让模型制定完整计划，再逐步执行。与 ReAct 相比，它对长任务的全局把控更好，但计划一旦制定就较难根据新信息动态调整。实践中常与 ReAct 混合使用：上层用计划保证方向，下层用 ReAct 处理单步执行的灵活性。

## 多智能体协作

当任务复杂度提升时，可以让多个 Agent 分工协作。常见做法包括：

- **角色分工**：每个 Agent 负责一个专门角色（例如研究员、撰写员、审查员），职责隔离使每个 Agent 的提示词和上下文更聚焦；
- **并行处理**：多个子任务同时执行，再由汇总节点整合结果，显著缩短总耗时；
- **互相评审**：让一个 Agent 检查另一个 Agent 的输出，提升结果质量。

多智能体系统的代价是通信开销与协调复杂度上升，因此并非越多越好，通常 3～5 个角色足以覆盖大多数复杂任务。

## 工具调用与 MCP

现代大模型普遍支持 Function Calling（工具调用）：开发者以结构化的方式声明工具的名称、参数与用途，模型在需要时生成对应的调用请求。

MCP（Model Context Protocol）是 Anthropic 于 2024 年底推出的开放协议，目标是统一模型与外部工具、数据源之间的接入方式。可以把它理解为「AI 世界的 USB-C 接口」：工具提供方实现一次 MCP Server，各种支持 MCP 的客户端都能直接接入，避免为每个平台重复适配。

## 工程化要点

把 Agent 从 Demo 做到可用，通常要处理这些问题：

1. **上下文管理**：多步任务会迅速撑爆上下文窗口，需要摘要压缩、按需检索等策略；
2. **失败恢复**：工具调用可能失败，系统需要重试、降级或人工接管机制；
3. **可观测性**：记录每步的输入输出与耗时，便于排查问题；
4. **评测**：用固定的任务集持续衡量 Agent 的成功率与成本，任何改动都应通过评测验证效果。
