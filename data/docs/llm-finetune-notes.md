# 模型微调笔记

## 什么时候需要微调

微调解决的是「模型不会做某类事」，而不是「模型不知道某件事」。如果问题是缺少领域知识（新政策、内部文档、实时数据），检索增强是更合适的方案；如果问题是输出风格、格式或固定任务的稳定性，微调才有明显收益。

一个实用的判断顺序：先试提示词 → 再试检索增强 → 仍不达标再考虑微调。微调的数据准备、训练与回归成本都远高于前两者。

## 主流方法

**全参数微调（SFT）**：更新全部权重，效果上限最高，但显存与数据量的要求也最高，且每个任务都要存一份完整模型。

**LoRA / QLoRA**：只训练低秩适配矩阵，显存占用大幅下降，适配权重只有几十 MB，可以在同一基座上按任务切换。QLoRA 叠加 4bit 量化后，单卡就能微调较大的模型，是当前性价比最高的方案。

**偏好对齐（DPO / RLHF）**：用「好回答 vs 坏回答」的成对数据对齐模型偏好，适合主观质量类目标（语气、 helpfulness），不适合注入事实知识。

## 数据怎么准备

数据质量决定微调的上限。常见做法是：从真实业务日志里抽样 → 人工改写为标准答案 → 去重与长度过滤 → 按比例切分训练/验证集。几千条高质量样本通常好过几万条噪声样本。

需要警惕数据泄漏：验证集与训练集有重叠时，指标会虚高，上线后立刻露馅。

## 与检索增强的取舍

- **知识更新频率高**（每天/每周）→ 检索增强，微调追不上更新速度。
- **要求可溯源**→ 检索增强，微调后的知识无法给出出处。
- **要求极低延迟或离线运行**→ 微调，省掉检索链路的耗时。
- **固定格式抽取、分类、风格迁移**→ 微调更稳，输出一致性更好。
- **两者结合**：用微调教会模型「怎么用检索到的资料」，再用检索提供事实，是常见的组合打法。

## 验收与回归

微调的验收必须包含三部分：目标任务指标、通用能力是否退化（ catastropic forgetting）、以及对抗样例（越权、提示注入、超长输入）。只盯着任务指标上线，很容易得到一个「专精一项、其余全崩」的模型。
