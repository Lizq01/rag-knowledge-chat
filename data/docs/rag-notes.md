# RAG 技术笔记

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）由 Lewis 等人在 2020 年的论文中提出。它的思路很直接：让大模型在回答前先「查资料」——从外部知识库中检索相关内容，再基于检索结果生成回答。

RAG 主要解决大模型的两个固有问题：一是知识截止（模型不知道训练数据之后的事情），二是幻觉（模型可能编造看似合理但错误的内容）。由于答案有检索内容作为依据，RAG 的另一个好处是**可溯源**：可以给出回答所引用的原文出处。

## 核心流程

RAG 分为离线索引与在线查询两个阶段。

**索引阶段**：文档加载 → 文本切分 → 向量化（Embedding）→ 存入向量库。

**查询阶段**：用户提问 → 问题向量化 → 检索相关片段 →（可选）重排 → 大模型基于片段生成回答。

## 文本切分策略

切分（Chunking）直接决定检索质量的上限。常见做法：

- **固定长度切分**：按字符数或 token 数切分，实现简单，但可能切断句子；
- **重叠切分**：在相邻块之间设置一段重叠区间（例如 50～100 字符），避免关键信息恰好落在边界处被切断，保证上下文的连续性；
- **语义切分**：优先按段落、标题等自然边界切分，让每个块尽量是一个完整的语义单元。

实践中常组合使用：先按段落聚合，控制每块不超过设定长度，超长段落再按句子边界二次切分。

## 向量化与向量库

Embedding 模型把文本映射为高维向量，语义相近的文本在向量空间中距离更近。中文场景常用的开源模型包括 BAAI 的 BGE 系列（如 bge-small-zh、bge-base-zh、bge-m3 等），其中 small 版本体积小、速度快，适合本地部署。

常见向量数据库：FAISS（本地库，适合中小规模）、Chroma（轻量嵌入式）、Milvus / Qdrant（服务化，适合生产规模）。小规模场景下也可以直接用 NumPy 做余弦相似度计算，无需引入额外组件。

## 混合检索与 RRF 融合

单一检索方式各有盲区：BM25 这类关键词检索擅长精确匹配（术语、编号、专有名词），但不懂同义改写；向量检索擅长语义相似，但对精确术语不敏感。把两者结合称为**混合检索**。

融合两路结果最常用的算法是 RRF（Reciprocal Rank Fusion，倒数排名融合），公式为：

    score(d) = Σ 1 / (k + rank_i(d))

其中 rank_i(d) 是文档 d 在第 i 路检索中的排名，k 是平滑常数，通常取 60。RRF 只使用排名、不使用原始分数，因此无需考虑两路分数的尺度差异，鲁棒且几乎不需要调参。

## 重排（Rerank）

检索阶段（召回）追求「不漏」，通常返回较多候选；重排阶段追求「精准」，对候选精细排序后只保留最相关的几条。

重排常用 Cross-Encoder 模型（如 BGE-reranker 系列）：它把「问题 + 候选文本」一起输入模型直接输出相关性分数，精度显著高于检索阶段的双塔向量模型，代价是速度较慢——所以只对少量候选使用。工程上也有用大模型直接给候选打分的做法，效果稳定、零额外部署成本。

## 评测

RAG 评测通常分两层：

**检索层**常用 Recall@K（期望文档是否出现在前 K 条结果中）和 MRR（期望文档排名的倒数均值）。

**生成层**关注回答质量，核心指标包括：忠实度（Faithfulness，回答是否完全基于检索到的内容、没有编造）和答案相关性（Answer Relevancy，回答是否切题）。实践中可用大模型作为裁判（LLM-as-Judge）对要点覆盖情况进行打分。

任何对切分、检索、重排参数的调整，都应该用固定评测集验证效果后再上线。
